# Diff annotation disclosure

Choose the presentation for each explanation:

1. Already explained in the tour? Link to the original code range; reveal and highlight it without
   opening a duplicate explanation or moving keyboard focus.
2. A self-contained aside that fits in one short paragraph? Use a popover only when preserving the
   surrounding code layout helps. It temporarily covers code, so use inline disclosure if the reader
   needs to keep the explanation open or compare it with another note.
3. Otherwise, use inline disclosure: a visible numbered title with details collapsed. Longer
   rationale, lists, and examples belong here. Dropdown menus are for actions, not explanations.

Label external links with the note title and before/after line range; numbers alone hide the target.
If the source is unavailable, retain the explanation with that status and omit the location action.
Use the reader's current Diff contract for implementation; component verification stays with its
owning workflow.
