# Bootstrap project verification

Select initial coverage for an explicitly requested project onboarding. Reuse an existing guide and
map; bootstrap extends their coverage rather than creating a competing location.

1. Inspect routes, commands, menus, public interfaces, tests, and project documentation. Identify
   the primary user surface and note other surfaces. Select three to five core user outcomes by
   default, or the user's named scope. Record selected features, entry points, relevant roles, and
   known omissions in the map index. An initial sample establishes useful coverage, not a whole-app
   proof.
2. Resolve intended outcomes from accepted requirements and authoritative product documentation. Ask
   only for decisions the repository cannot establish; leave dependent recipes incomplete while
   progressing independent coverage. Current output alone cannot define correctness.
3. Identify documented startup, existing interaction harnesses, observable effects, and isolation
   constraints. Confirm the target starts and doctor can identify its build, access, and required
   state using project-owned setup. Missing provisioning follows the setup owner and
   [blocker procedure](../../anaphor-verify/references/evidence.md).
4. Return the selected scope to the creation procedure. Its recipe format, location selection, and
   execution requirements apply to every seeded recipe. Record gaps separately from proven entries;
   a single successful feature cannot certify the rest.

**Done:** selected outcomes have authoritative expectations and executable prerequisites, and the
index names initial coverage and omissions. Bootstrap delivery completes only after the creation
procedure proves every seeded recipe and its discoverability, with evidence surviving cleanup.
